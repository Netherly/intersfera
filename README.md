# intersfera

Внутренний сервис обработки входящих обращений.

Сейчас готов каркас: вход, меню, пользователи и роли, реестр обращений, карточка, статусы, файлы и история.

## Запуск

```bash
docker compose up --build
docker compose exec api npx prisma migrate dev --name init
docker compose exec api npm run seed
```

Интерфейс — http://localhost:5174, API — http://localhost:4001/api.

Первый вход: `admin` / `admin`.

## Публикация на Vercel и Neon

Один проект Vercel отдаёт интерфейс и API с одного адреса. База — Neon. Почта остаётся выключенной: поля SMTP и IMAP пустые, экран почты сообщает, что она не настроена. Загруженные файлы обращений живут только внутри одного вызова функции. Реестр, карточки, пользователи и материалы лежат в Neon.

1. Создайте проект в [Neon](https://neon.tech) (Postgres). Регион лучше тот же, что выберете у Vercel.
2. Импортируйте репозиторий в [Vercel](https://vercel.com). Корень проекта — корень репозитория, не `frontend` и не `backend`. Команды сборки уже лежат в `vercel.json`.
3. Подключите интеграцию Neon к проекту Vercel или задайте переменные сами:
   - `DATABASE_URL` — pooled-строка, в хосте есть `-pooler`.
   - `DIRECT_URL` — прямая строка, без `-pooler`. Если её нет, сборка возьмёт `DATABASE_URL_UNPOOLED`, затем `DATABASE_URL`.
   - `JWT_SECRET` — длинная случайная строка.
4. `VITE_API_URL` на Vercel не задавайте. Сборка сама ходит на `/api`.
5. Задеплойте. Сборка применит миграции и выполнит сид: роли, категории, материалы и супер-админ `admin` / `admin`.

Повторный деплой дополняет справочники и оставляет уже созданного админа.
